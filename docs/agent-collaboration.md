# 多 Agent 协作

0.16.0 开发版提供多个 Codex 的协作流程。侧栏进入“多 Agent 协作”，点击 **+** 创建任务组。

## 使用流程

1. 选择有初始提交、工作区干净的 Git 仓库根目录，填写整体目标。
2. 手动拆分为 1–8 个任务，给每个 Worker 写清负责范围、执行要求和验收标准；设置并行上限 1–4。
3. 启动后后台分别创建 Git worktree 和 Codex 会话，使用当前聊天选择的模型、推理强度与权限。排队任务随运行槽位释放启动。
4. 成员卡片显示排队、执行、待审批、失败、结果不确定等状态。点击“打开成员会话 / 处理审批”进入原生审批或澄清卡片；成员会话由调度器控制，不能直接发送额外聊天任务。
5. 可以给成员或全组留言。成员有收件箱、状态查询和留言工具；留言保存在服务器，不会自动中断对方。成员的提示词要求在开始、重要决策及结束前检查收件箱，但不能保证模型每次都会遵守。
6. 所有 Worker 都结束后，主控在独立 worktree 中审阅成果，使用整合工具收集成功任务、处理交叉修改并测试，最后汇报结果。失败项会明确包含在主控输入中。
7. 点击“审阅成果差异”检查每个 Worker 或汇总成果。点击“应用汇总成果到项目”才会更新原项目。

主控只在 Worker 全部结束后启动；这一版由用户手动拆分任务，不包含自动拆分、运行中重新分派、跨 CLI 编排或跨服务器团队。留言是持久化协作信息，不是实时抢占指令。

## 工作区与成果

协作 worktree 位于仓库 Git common directory 内的 `codepax-teams/<runId>/<taskId>`，不污染原工作区的未跟踪文件列表。分支名为 `codex/team/<runId前12位>/<taskId>`。

成员完成时，后台使用临时 Git index 收集该 worktree 的已跟踪和未忽略的新文件，为成果创建以启动基线提交为父节点的快照提交，记录在 `codex/team-results/<runId>/<taskId>`。不会改变成员原 index、工作文件或已有提交历史；快照提交署名为 `Code Pax <agent@codepax.local>`。被 Git 忽略的文件不会进入成果。

主控的整合工具将 Worker 快照 cherry-pick 到主控 worktree；发生冲突时回退这一次 cherry-pick，保留之前成功整合的结果，返回错误给主控。主控可以自行分析差异、修复交叉修改。正常 Git 配置和 hooks 仍然生效。

应用汇总成果要求原项目仍在启动时的分支、工作区干净且 HEAD 未前进。后台仅执行 fast-forward；不会重置用户改动。原分支有新提交时需要自行审阅成果分支并合并。重复应用相同操作会返回原回执，不重复执行。

worktree、成员会话和成果分支会保留供检查；当前不自动删除或回收。worktree 隔离避免同时修改同一份工作文件，并不是 SSH 账号或权限沙箱。Full Access 的成员仍然拥有所选 CLI 的实际权限，且 Git 元数据由 worktree 共享。

## 持久化、断线与重试

- 协作计划、成员状态、留言、快照和应用记录保存在原有 SQLite 数据库的 `teams` 表中；任务在服务器后台执行，iPad 断开不会停止协作。
- API 写操作及成员工具写操作使用持久化操作 ID 去重。iPad 将未确认操作存入本设备钥匙串，收到回执后删除；断线后不会换一个 ID 自动重发。
- Worker 发送结果不确定时占用原运行槽位，不自动重试；先检查成员会话和服务器状态。已失败、中断或取消的成员可显式重试，新会话使用同一 worktree，保留之前文件。主控启动后不能重新分派已结束的 Worker，可另建协作组补做。
- 后台重启会将活动协作标记中断，不自动恢复执行。排队和执行中的任务需要显式重试，已完成成果和留言保留。不会因为打开历史自动触发任务。
- “停止协作”会阻止后续分派并中断活动成员，包括在取消期间才到达的 `turn/started`。实际结束状态以 App Server 通知为准；结果不确定的任务不伪装为已停止。
- 每个协作组最多 200 条留言；列表最多返回最近 100 组摘要，打开详情时读取完整成果及最近 50 条留言；差异预览最多 128 KiB，完整成果仍在 Git 分支中。最多同时运行四组协作，每组的 Worker 数遵守各自并行上限，主控不计入 Worker 槽位。

## 接入方式

`backend/collaboration.py` 负责计划、调度、worktree、成果和成员工具。原生 Codex 通道继续由 `bridge.py` 负责；新增能力通过 `status.capabilities` 中的 `collaboration` 声明，旧后台不会显示为已支持。

客户端 API：

| action | 用途 |
| --- | --- |
| `teamCreate` | 创建整体目标、Worker 清单及执行设置 |
| `teamList` | 读取最近协作组与成员状态摘要 |
| `teamRead` | 读取指定协作组成果及最近留言 |
| `teamMessage` | 用户给指定成员或全组留言 |
| `teamCancel` | 停止分派并中断成员 |
| `teamRetry` | 显式重试失败、中断或取消的成员 |
| `teamDiff` | 读取某个成员的成果差异 |
| `teamApply` | 将主控快照 fast-forward 应用到原项目 |

成员会话通过 App Server 的实验性 `dynamicTools` 接入 `codepax_team_status`、`codepax_team_inbox`、`codepax_team_message`；主控另有 `codepax_team_integrate`。工具调用由服务端根据实际 thread、turn 和成员身份限定范围，不能通过参数选择另一个协作组。执行工具在独立处理线程中进行，不阻塞 JSON-RPC 读取线程。

这需要支持该实验性接口的 Codex CLI；已核对服务器 Codex 0.164.0 的协议 schema 并完成真实模型联调。若服务器不接受工具定义，会显示成员启动失败，不会静默退回没有协作能力的普通任务。
